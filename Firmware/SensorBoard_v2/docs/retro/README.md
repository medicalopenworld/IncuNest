# Retros (aprendizajes del loop)

Aquí aterrizan los aprendizajes que `retro-improver` extrae al cerrar cada iteración del loop engineering (paso 7, obligatorio al cerrar una sub-tarea de épica — lo blinda el hook `require-retro.sh`). Cada archivo describe qué costó, qué se repitió y qué mejora concreta se aplicó al propio framework (`.claude/` o `CLAUDE.md`), o bien registra el hallazgo como descartado con motivo cuando no supera el filtro de segunda ocurrencia.

## Convención de nombres

`docs/retro/<AAAA-MM-DD>-<slug>.md`, un archivo por retro.

## Filtro de segunda ocurrencia

No se sistematiza una regla por un fallo de primera vez (puede ser casualidad). Se enruta a `.claude/` (hook/rule/skill/agente) o a `CLAUDE.md` solo cuando el patrón se repite, tiene coste observable, o es claramente generalizable. Lo demás se anota aquí como descartado, con el motivo.
