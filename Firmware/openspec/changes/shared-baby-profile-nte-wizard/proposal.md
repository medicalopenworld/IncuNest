## Why

Activating AIR or SKIN temperature control today asks nothing about the baby: an optional, disconnected "AUTO AIR" popup (`Display_HMI/src/tasks/UITask.cpp:901-1481`) can suggest an air setpoint from an existing NTE table, but nothing is persisted and SKIN mode never sees it. This makes the baby-data wizard mandatory on every AIR/SKIN activation, adds persistent baby profiles owned by `motherBoard`, and extracts the NTE calculation into `Firmware/shared/` as the single source of truth consumed by both boards — closing the door on the two clinical tables silently drifting apart, and laying the groundwork for the SKIN-mode safety guardrail (sub-project B, out of scope here).

This is **sub-project A of 3** from the approved design doc: `Firmware/docs/superpowers/specs/2026-08-11-baby-profile-temp-control-wizard-design.md` (full data model, protocol, wizard flow, edge cases and testing strategy — this proposal formalizes it as an OpenSpec change, it does not restate it). Sub-projects B (SKIN NTE guardrail/alarm) and C (unified time service + GPRS time sync) are explicitly out of scope.

Boards affected: **all three** — `Firmware/shared/` (new `nte_table.h`/`.cpp`, genuinely shared by design), `motherBoard` (data model, protocol, NTE computation), `Display_HMI` (wizard UI, protocol client, no more local NTE calculation).

This also touches a documented area of risk: the motherBoard<->HMI protocol is ASCII CSV with no CRC (`Firmware/docs/known_issues.md` covers phantom alarms and UART flooding in this same channel) — every new `PROFILE_*`/`CTRL,PROFILE_*` line must follow the existing field-count/numeric validation and silent-discard convention (`.claude/rules/security.md`), not reintroduce a variant of an already-fixed class of bug.

## What Changes

- **New shared NTE engine** (`shared/include/nte_table.h`, `shared/src/nte_table.cpp`): `calculateNteRange(weightGrams, gestWeeks, ageDays) -> NteRange{lo, hi, mid, estimated}`, extracted from `Display_HMI/src/tasks/UITask.cpp:901-1060+`. `shared/` gains its first `.cpp` (today header-only) — `library.json`/both `platformio.ini`s and motherBoard's `[env:native]` `build_src_filter` need to account for it.
- **New motherBoard baby-profile data model**: 3 active slots in NVS (`Preferences`, namespace `NS_BABY`), FIFO eviction by creation `seq` on a 4th profile; permanent append-only history ring buffer in LittleFS (`/littlefs/baby_history.log`, capped at 1,000 records). Age in days is always derived at question time from `admissionEpoch` + synced time, never persisted.
- **New `NS_BABY/activeSeq` NVS key (`0` = none), persistent across reboot**: protects the profile currently driving an active AIR or SKIN control loop from FIFO eviction. It is set when the wizard's Apply step completes for either mode, and cleared when that control mode is switched off. The FIFO eviction rule above now excludes `activeSeq` when choosing which slot to evict on a 4th profile — it picks the lowest `seq` among the *non-active* slots. Since only one control loop is active at a time, at least 2 of the 3 slots are always eligible in normal operation; as a defensive fallback (not expected to trigger), if no eligible slot exists, 4th-profile creation is rejected with an error instead of evicting the active profile.
- **New weight-evolution history** (per active baby): every non-`SKIP` weight answered in the wizard is appended, deduplicated against the last stored point, to a per-baby circular file `/littlefs/weight_active/<seq>.bin` (capped at 1,000 points, ~6 KB/baby). When a baby is evicted from an active slot, its weight file is **moved** (not discarded) to `/littlefs/weight_archive/<seq>.bin`, drawing from a **shared 600 KB byte budget** across all archived babies (tracked by an index of bytes-used per `seq`). The oldest archived baby's `baby_history.log` audit record and `weight_archive/<seq>.bin` file are always evicted **together**, the moment either the 1,000-record audit cap or the 600 KB weight-archive budget is hit — never independently, so a historical entry never has one without the other.
- **New/changed protocol messages** (`HMI,PROFILE_LIST_REQ`, `CTRL,PROFILE_LIST`, `HMI,PROFILE_NEW`, `HMI,PROFILE_SELECT`, `HMI,PROFILE_WEIGHT`, `CTRL,PROFILE_RANGE`, `HMI,PROFILE_AGE_MANUAL`) — **BREAKING**: removes the undocumented `babyWeightGrams`/`babyGestWeeks`/`babyAgeDays` fields currently appended to the recurring `HMI,...` line (`Display_HMI/src/tasks/CommTask.cpp:90-96`, also consumed by `motherBoard/src/tasks/CommTask.cpp`). `Firmware/PROTOCOL.md` is updated in the same change, correcting the existing field-count drift against the real message.
- **Cloud telemetry to ThingsBoard keeps publishing baby data — intentionally, not a leak.** `motherBoard/src/tasks/GPRS.cpp:800-806` and `motherBoard/src/tasks/Wifi_OTA.cpp:893-899` already publish `weightGrams`/`gestWeeks`/`ageDays`; they keep doing so, now reading from `modules/baby_profile/` instead of the removed `hmi_cmd_msg.baby*` fields. This change **adds `name` and `outcome`/`dischargeEpoch` to that same published set** on both the GPRS and WiFi paths — an explicit product decision (the Ministry of Health has access to this data via ThingsBoard), documented so implementation doesn't have to guess whether the baby's name and clinical outcome belong in cloud telemetry.
- **New Display_HMI wizard state machine**, replacing the current AUTO AIR popup, triggered on every OFF->ON transition of the AIR or SKIN switch (even if already run earlier in the session): profile list/new/select -> weight (or SKIP) -> wait for range (asking for manual age if unknown) -> summary -> apply. AIR keeps its adjustable setpoint; SKIN starts fixed at 36.5°C with no manual arrows. Closing before completion leaves the switch OFF; an incoming critical alarm closes the wizard and yields the screen.
- Removal of local NTE computation from `Display_HMI` — it only renders what motherBoard returns.
- **New `BabyProfile` fields `dischargeEpoch`/`outcome`** (uint32/enum: 0=Unknown, 1=Survived, 2=Deceased, 3=Transferred), persisted on the active slot and carried into the `baby_history.log` audit record on archival, so the permanent record always reflects the final outcome.
- **New explicit-discharge path** (`HMI,PROFILE_DISCHARGE,<seq>,<outcome>`): archives the profile immediately (same archival routine already used by FIFO eviction — audit-record append, weight-file move, unified 600 KB/1,000-record retention check) and frees its active slot right away, instead of waiting for a 4th profile to force it out. Independent of AIR/SKIN control state (does not affect it either way). A profile that reaches the FIFO fallback without ever being explicitly discharged is archived with `outcome=Unknown, dischargeEpoch=0` — a valid, expected state, not an error. This gives the existing single archival routine (from `baby-profile-storage`) a second entry point, in addition to FIFO eviction.
- **New "Babies" top-bar button + history screen** (new capability, see below): active profiles (with a "Discharge" action) listed first, then archived profiles paginated 10/page (`HMI,PROFILE_HISTORY_REQ,<page>` -> `CTRL,PROFILE_HISTORY,<page>,<totalCount>,<n>,{...}xn`). Tapping any baby (active or archived) opens a weight-evolution chart (new LVGL `lv_chart` widget), fed by `HMI,WEIGHT_HISTORY_REQ,<seq>` -> `CTRL,WEIGHT_HISTORY,<seq>,<n>,{<dayOffset>,<weightGrams>}xn`, with motherBoard downsampling to a maximum of 50 points per response so the reply always fits a single protocol line.

## Capabilities

### New Capabilities
- `nte-calculation-engine`: the shared, pure `calculateNteRange()` function and its `NteRange` result type, single source of truth for both boards.
- `baby-profile-storage`: motherBoard-owned persistence — 3 active NVS slots, FIFO eviction by `seq`, LittleFS audit-history ring buffer, age-at-question-time derivation, per-baby weight-evolution history (active + archived files) with its own 600 KB shared archive budget, and the unified audit+weight-archive eviction rule.
- `baby-profile-protocol`: the motherBoard<->HMI `PROFILE_*`/`CTRL,PROFILE_*` message set, including replacement of the legacy `babyWeightGrams`/`babyGestWeeks`/`babyAgeDays` fields and the `PROTOCOL.md` field-count correction.
- `temp-control-activation-wizard`: the Display_HMI state machine and screens that make baby-data entry mandatory on every AIR/SKIN activation, including the SKIP-weight and unknown-age-time branches, cancel-leaves-OFF behavior, and alarm-interrupts-wizard behavior.
- `baby-history-viewer`: the Display_HMI "Babies" top-bar button, the active+archived (paginated) history screen with the discharge action/outcome picker, and the per-baby weight-evolution `lv_chart` screen. Kept **separate** from `temp-control-activation-wizard` because it is a distinct entry point (top-bar button, not the AIR/SKIN switches) with its own screens and its own lifecycle (browsing/discharging any baby, not just the one being activated) — bundling it into the wizard capability would conflate "activate control for baby X" with "browse/discharge/inspect any baby, active or archived."

### Modified Capabilities
(none — this is a new OpenSpec root with no existing `openspec/specs/`; the AUTO AIR popup and the legacy baby fields being replaced were never formalized as OpenSpec capabilities)

## Impact

- **Affected code**: `shared/include/nte_table.h` (new), `shared/src/nte_table.cpp` (new), `shared/library.json`; `motherBoard/include/`/`src/` new `NS_BABY` storage module + LittleFS audit-history log + LittleFS weight-evolution active/archive files + protocol handling (likely under `modules/comm/` and a new profile-storage module, see `.claude/rules/embedded-motherboard.md`); `motherBoard/platformio.ini` (`[env:native]` `build_src_filter` extended to cover the new pure logic, `partitions/ESP32S3_8MB.csv` unchanged); `Display_HMI/src/tasks/UITask.cpp` (AUTO AIR popup replaced by the wizard, local NTE calculation removed, new "Babies" top-bar button + history/chart screens added), `Display_HMI/src/tasks/CommTask.cpp` (new `PROFILE_*`/`WEIGHT_HISTORY_*` messages, legacy baby fields removed); `Firmware/PROTOCOL.md` (updated, drift corrected).
- **Affected consumers of the legacy fields**: `motherBoard/src/tasks/CommTask.cpp:413-418` (recurring-line field mapping, removed alongside the breaking protocol change). `motherBoard/src/tasks/GPRS.cpp:800-806` and `motherBoard/src/tasks/Wifi_OTA.cpp:893-899` are **not removed** — they are updated to re-source `weightGrams`/`gestWeeks`/`ageDays` from `modules/baby_profile/` and to additionally publish `name`/`outcome`/`dischargeEpoch` (see "Cloud telemetry" above).
- **Testing**: new Unity tests in motherBoard's `[env:native]` for `nte_table` (pure), the FIFO-by-`seq` eviction logic (pure), the weight-point dedup rule (pure — skip if unchanged from the last stored point), the unified audit+weight-archive eviction trigger (pure — either cap hit evicts the oldest `seq` from both), the shared archive routine's two entry points (FIFO auto-evict and explicit discharge, pure decision logic), the weight-history downsampling-to-50 algorithm (pure), and `PROFILE_*`/`WEIGHT_HISTORY_*` message field-count/numeric validation — per `.claude/rules/testing.md`, mandatory since these are pure/hardware-free and extend the native-covered filter. NVS/LittleFS persistence (including the weight-archive 600 KB budget accounting), the LVGL wizard, and the LVGL history/chart screens are manual-verification only (no test env exists for the rest of motherBoard or for any of Display_HMI).
- **Out of scope**: sub-project B (SKIN-mode NTE safety guardrail/`SKIN_SERVO_RANGE_LIMIT_ALARM`) and sub-project C (unified time service + GPRS time sync) — both depend on this change but are separate future proposals.
